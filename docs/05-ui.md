# 界面

> 参考 Claude 移动端。**神似，不形似** —— 不追像素，追同一套语言。

---

## 1. 原则

一开始我拿 Claude 的截图逐像素量，然后往 CSS 里写 `padding-top: 57px`、
`margin: 37px` 这种数字。那是错的：

- 换机型、换字体渲染、换状态栏高度，全部漂掉
- 数字没有含义，下一个人看不懂为什么是 57

改成：

1. **颜色/圆角/字号定义成 `@theme` 令牌** → Tailwind 自动生成工具类
   （`bg-surface` / `text-muted` / `rounded-card`）
2. **间距一律用 Tailwind 自带刻度**（`p-2`=8 `p-4`=16 `gap-6`=24 `size-9`=36）
3. **顶部/底部留白交给系统**：Android 开 edge-to-edge，页面用
   `env(safe-area-inset-*)` —— 换刘海、换手势条都不用改 CSS
4. **图标统一规格**：内联 SVG，16 个图标全部 `viewBox="0 0 20 20"` +
   `stroke-width 1.8` + `round`，墨迹（几何 + 半个描边）落在 13.6–16.8。
   同一行放不同图标时光学尺寸才对得上 —— 之前这几处都不齐：
   `menu` 是 17×15 的横向画布 + 1.9 描边、`gear` 是 24 画布（描边实际只有 1.58）、
   剩下的描边在 1.6/1.7/1.9/2.1 之间乱跳，`sparkle` 只有 12.8 而和它同一列的
   `clock` 有 16.6。只有 `back` / `chevron` 两个小尖角故意画小（贴着文字用）。
   头部左边 = 两条横线的菜单（上一条满宽、下一条 3/5），
   右边 = 「圆气泡 + 左下小尾巴 + 加号」的新对话。
   逐个图标的实测尺寸表在 `web/src/components/Icon.svelte` 顶部注释里。
5. **点击 / hover 一律没有任何反馈**：不写 `active:**` / `hover:**` / `focus:**`
   工具类，也不要 `:active` 提亮、按下变色、缩放、ripple。手指按下去界面
   纹丝不动，这是刻意的（Claude 也这样）。实现上不是靠「大家记得别写」，
   而是 `app.css` 里用 `@custom-variant` 把 `active` / `hover` / `focus` /
   `focus-visible` 四个变体**整体改写成永远不匹配** —— 写了也等于没写。
   真机上的 sticky hover / 默认 focus 外框另有 `filter/outline` 兜底。
   （这条被 agent 反复改回去过，所以加了硬性拦阻。）

CSS 从 17.8 kB 降到 13.8 kB，而且没有一处魔法数字。

## 2. 取色（实测自 Claude 截图）

| 用途 | 值 | 令牌 |
|---|---|---|
| 背景 | `#151515` | `ink` |
| 输入卡片 | `#20201f` | `surface` |
| 用户气泡 | `#2c2c2a` | `bubble` |
| 圆形按钮 / 药丸 | `#313131` | `control` |
| 分隔线 | `#262624` | `hairline` |
| 正文 | `#f9f9f7` | `fg` |
| 次要文字 | `#97958d` | `muted` |
| 更弱 | `#6f6d66` | `faint` |
| 选中 / 链接 | `#6da7ec` | `accent` |

几个值得注意的点：

- **背景不是纯黑**（`#151515`），是暖调近黑。纯黑在 OLED 上对比过强，看着累
- **正文不是纯白**（`#f9f9f7`），带一点暖
- **语义色刻意去饱和**（`ok` `#7fb37f`、`warn` `#d9b87f`、`bad` `#d98a8a`），
  不抢主色
- **`accent` 是蓝，不是绿**。实测 Claude「选择模型」面板里的**勾选**和脚注**链接**
  都是 `#6da7ec`。绿色另有用途（“设备连接正常”那个点用 `--color-ok`）——
  绿 = 状态，蓝 = 可点 / 已选。

### 三层的颜色关系（照 Claude 实测）

| 层 | 底色 | 令牌 |
|---|---|---|
| 页面 / 面板 | `#151515` | `ink` |
| 面板里的卡片 | `#20201f` | `surface` |
| 徽章 / 药丸 / 用户气泡 | `#2b2b2a` / `#2c2c2a` | `bubble` |

关键是**面板和页面同一个色**（都是 `ink`）：面板不是自己变亮，而是靠遮罩把页面
压暗（`#151515` → `#0e0e0e`，`bg-black/35`）才“浮”起来的。里面那层卡片才是
`surface`。原来反着用（面板 `surface`、卡片 `bubble`），看着就比 Claude “高一档”。

## 3. 布局

```
┌──────────────────────────────┐
│ ☰                       +    │  header（左：抽屉，右：新对话）
│                              │
│         来思考些什么?          │  空态（居中）
│                              │
│  ┌────────────────────────┐  │
│  │ 与 agent 对话…          │  │  composer
│  │ (+) [模型]        (↑)  │  │
│  └────────────────────────┘  │
└──────────────────────────────┘
```

**底部那三个 tab 去掉了** —— 界面/事件挪进抽屉（点 ☰ 或 +）。

### 宽屏：侧边栏和对话**并排**

同一份界面在两种宽度下是两种形态（断点 56rem = 896px，见 `lib/wide.svelte.ts`）：

```
窄屏（手机，上面的图）             宽屏（电脑，侧边栏展开时）
┌────────┬───────────────────────────┐
│ 搜索对话… │                       +   │
│        │                           │
│ 💬 会话 │   对话（占满剩下的宽度）   │
│ 💬 会话 │                           │
│        │   ┌──────────────────┐   │
│ (⚙)    │   │ 输入              │   │
└────────┴───────────────────────────┘
```

- 宽屏下侧边栏**默认收起**（对话区就占满整个窗口），点左上角的菜单才展开 ——
  而且刷新之后永远是同一个样子：不然每次刷新都会看它“从关闭弹到打开”。
- 展开之后它是一栏**并排**的：没有遮罩、不能往左拖、**不接返回键**（它不是
  “盖在上面”的东西），收起 / 展开是 180ms 的宽度动画。搜索框 / 列表 / 底栏那
  一整段是同一个 snippet，两边共用，只有外层容器不同（`fixed` 抽屉 → `static` 一栏）。
- 头部那个菜单按钮**两个宽度下都在**：窄屏开抽屉，宽屏是收起 / 展开。所以哪怕
  侧边栏收着，也随时能找回来（也能从右上角开新对话）。
- **为什么用 `matchMedia` 而不是纯 CSS 断点**：两种形态的差别不只是样式，还有
  上面那些行为（返回键、拖拽、遮罩、菜单按钮）—— CSS 管不了。
- 对话区**把剩下的宽度全部拿走**（不限宽）：多出来的地方给正文，不空着。
- **窄屏那一套一下都没少**：抽屉的遮罩、往左拖、跟手返回（`__predictiveBack`）
  都还是原样 —— 分栏只是多了一条分支，不是把抽屉改成常驻。

### 底部面板的尺寸（对 Claude 截图逐项实测）

原则：**要神似，不追像素对齐** —— 量出来的值取 Tailwind 刻度里**最接近的一档**。

| 项 | Claude 实测 | 我们 | 说明 |
|---|---|---|---|
| 面板顶部圆角 | 43px | `rounded-4xl`（32px） | 刻度最大就是 4xl；比 3xl（24）近得多 |
| 卡片圆角 | 15～16px | `rounded-2xl`（16px） | 一致 |
| 面板左右内边距 | 12.2px | `px-3`（12px） | 一致 |
| 卡片内边距 | 14 / 16px | `px-3.5 py-4` | 一致 |
| 列表行内边距 | 12 / 14px | `px-3.5 py-3` | 一致 |
| 行分隔 | 1.9px 的**面板色** | `border-b-2 border-ink` | 不是 1px hairline |
| 卡片间距 | 12.2px | `gap-3` | 一致 |

两个容易看漏的：

- **行分隔是 2px 的面板色**，不是 1px 的 `hairline`。实测那 2px 就是 `#151515`，
  看着像“行之间有缝”而不是“一条线”。
- **勾选是 `accent` 蓝**，不是白。

验证方法：`just dom-audit --shot <目录>` 把每屏截下来，再用同一套测量脚本量像素；
或者直接读计算样式（面板圆角、卡片内边距那些值上面就是那么对出来的）。

### 正文的规格（一处刻意的例外）

| 位置 | 颜色 | 字号 |
|---|---|---|
| 回答正文（消息列表里的 Markdown） | `fg` 100% | 16px |
| **思考面板正文** | **`fg` 90%（`text-fg/90`）** | **15px** |
| 工具面板正文（命令 / 输出 / diff） | `fg` 100% | 13px mono |
| 思考行（列表里那行预览） | `muted` | 14px |

**思考面板那处是故意的**：思考是「想清楚才看」的东西，比回答暗 10%、小 1px，
不该和答案抢注意力。工具面板的正文**没有**任何改色（全对比度，代码要看得清），
它里面真正次要的东西（chips、「输出」标签、完整输出路径）用 `muted` / `faint`。

### 工具面板：模型看到的，这里都看得到

工具结果是一个 JSON，原样进了模型的上下文。面板以前只挑几个字段显示，`timed_out`、
`signal`、`urls`、搜索的 `count`/`provider`、图片宽高这些模型看得到、人看不到 ——
两边看到的不一致，就没法判断模型为什么那么推理。现在（`web/src/lib/toolview.ts`）：

1. 认识的字段各有样式：正文 / diff / 错误 / 药丸 / 图片 / 网址列表
2. **剩下的字段一个不藏**，列在「其他字段」里；取字段时类型对得上才算用掉，形状
   不对的（比如 `exit_code` 给成字符串）也会落进这里。以后工具多返回一个字段，
   不改前端也会出现
3. 底部折叠着「模型收到的原始结果」（排好版的同一份 JSON；带图时注明另附了图）。
   还在跑的阶段性输出没有这一节 —— 模型还没收到
4. 参数同理：主行放最关键的那个，其余参数（bash 的 `timeout`、read 的
   `offset`/`limit`、edit 新建时的 `content`、改失败时的 `edits` …）列在下面

全仓库只有这一处透明度变体是一次性的（`text-fg/90`），其余 6 处都有规律：
状态药丸 `bg-ok/15` `bg-bad/15` `bg-warn/15`、失败附件 `border-bad/50`、
菜单阴影 `shadow-black/60`。它是从 token 派生的（改 `--color-fg` 会跟着变），
所以没单独给 token，但记在这里 —— 免得下次有人当成“忘了统一的散落值”再改一遍。

### 三处顶栏的**顶部**对齐

对话页 / 抽屉 / 查看器（打开的 HTML、图片、文本）的顶栏都从**同一条线**开始：
`env(safe-area-inset-top) + 4px`。切页时内容不会上下跳。

**但里面的控件不高一样高** —— 各按自己的性质来：

| 位置 | 顶栏 | 控件 |
|---|---|---|
| 对话页 header | `36px + 安全区` | 菜单 / 新对话，28×28 图标按钮 |
| 查看器 header | `h-[var(--hdr)]` + `pt-[env(safe-area-inset-top)]` | 返回键 28×28 + 标题 |
| 抽屉顶部 | 不显式定高（搜索框有多高就多高） | 搜索框 48px（`py-3` + 16px 字） |

两个坑：

- `--hdr` **含安全区**（它是给浮动 header 用的总高）。拿它当高度又加
  `items-center`，内容就被居中在那段安全区里了 —— 真机上（安全区 66px）
  查看器返回键跑到 top=37，钻进状态栏（踩过）。要当内边距扣掉：
  `h-[var(--hdr)] pt-[env(safe-area-inset-top)]`
- 搜索框是**输入控件**，不是图标按钮：为了凑 36px 把它压成 28px 会很难看
  （踩过）。顶栏对齐的是顶部，不是控件高度。

改一处要同步 `--hdr`：它还管着顶部渐隐的高度（`calc(var(--hdr) + var(--fade-top))`）
和消息列表的顶部留白，不然第一条消息会停在渐隐里。

### 输入卡片

结构就三层，没有多余 div：

```svelte
<div class="mx-4 mb-[calc(1rem+env(safe-area-inset-bottom))] flex flex-col gap-3
            rounded-card border border-hairline bg-surface p-3">
  <textarea class="…" />
  <div class="flex items-center gap-2">
    <button class="size-9 rounded-full bg-control">+</button>
    <button class="h-9 rounded-full bg-control px-4">模型名 · 中等</button>
    <div class="flex-1"></div>
    <button class="size-9 rounded-full">↑</button>
  </div>
</div>
```

发送键空态是暗的，有字才变白底黑箭头 —— 和 Claude 一致。
药丸上是**模型 + 当前思考强度**（`gpt-5 · 中等`，强度 muted）：强度直接决定
「要等多久」，藏在面板里没道理。没配模型时只有「未配置模型」。

### 「+」= 添加附件，复用底部面板

以前「+」是把抽屉打开（和左上角徒增一个入口）。现在它管附件。抽屉继续
只走左上角那个菜单图标。

入口**不是就地弹的小菜单，而是直接复用 `Sheet`** —— 同一个抓手、标题、
遮罩、下拉/返回键关闭，只换正文。一屏三个等宽大卡片（相机 / 照片 / 文件），
图标在压暗的圆槽里、标签在下面，和 Claude 的「添加到会话」一致。

- **不加左上角的叉**：`Sheet` 本来就没有关闭按钮（下拉、点遮罩、返回键都能关）。
- **高度贴合内容**（`minClass="min-h-0"`）：只有三张卡片时不用撑到 45% 屏高，
  留一片空白。其他面板仍用默认的 `min-h-[45dvh]`。
- `AttachSheet.svelte` 只负责卡片；选完后的收尾（关面板 + 拉起选择器）
  交回 `Composer`。以后要加 Skills 就往面板下面再放一行，不改这三段式。

三个入口在页面里就是三个隐藏的 `<input type=file>`，壳里用
`WebChromeClient.onShowFileChooser` 接住（不实现它的话，WebView 里点文件
输入**一点反应都没有**，也不报错）：

| 入口 | input | 壳里怎么处理 |
|---|---|---|
| 相机 | `accept="image/*" capture="environment"` | `isCaptureEnabled` → 直接拉 `ACTION_IMAGE_CAPTURE` |
| 照片 | `accept="image/*" multiple` | `ACTION_PICK_IMAGES`（系统 Photo Picker 的相册网格）|
| 文件 | `accept="application/pdf,.pdf"` | `ACTION_OPEN_DOCUMENT`（SAF）|

- **刻意不用 `FileChooserParams.createIntent()`**：它发 `ACTION_GET_CONTENT`，
  Android 13+ 上会命中系统 Photo Picker。实测 Pixel 10 / Android 16 上
  选完照片点「完成」回来，`FileChooserParams.parseResult` 拿不到任何 URI
  （`uris=0`）→ WebView 的 `<input>` 不触发 change，界面上就像「选了但没加进去」。
  Photo Picker 还有个已知坑：它的 proxy URI 会让 Chromium 报
  `ERR_UPLOAD_FILE_CHANGED`（WordPress/GutenbergKit 也因为这个换掉了
  `GET_CONTENT`）。
- **照片走 `ACTION_PICK_IMAGES`**：就是那个相册网格（和 Claude 的「照片」一样），
  结果契约清楚且我们实测能拿到（单选 `intent.data`）；拿不到时退回
  `ACTION_OPEN_DOCUMENT`。
- **文件走 `ACTION_OPEN_DOCUMENT`**（SAF）：比 `GET_CONTENT` 稳，且支持把
  可持久读权限拿走。
- **结果自己解**，不用 `FileChooserParams.parseResult`：先收 `clipData`，再收
  `data`，再扫 `EXTRA_STREAM`；都拿不到才当取消（并把整个 Intent 打进日志）。

- **相机输出走 MediaStore**（`contentResolver.insert` 拿一个 `content://` URI
  当 `EXTRA_OUTPUT`），不用 `file://`（targetSdk 24+ 直接抛
  `FileUriExposedException`），也不引 FileProvider / AndroidX。用户取消就
  把那张空图删掉。
- **「文件」只在模型吃 PDF 时出现** —— `store.capabilities.pdf`，
  `/api/health` 给的值。不支持 `file` 内容块的端点接了 PDF 会直接 400，
  所以宁可不显示。图片不做这个限制：视觉能力现在基本都有。
- **文件名先 `encodeURIComponent`**：HTTP 头只能是 ISO-8859-1，中文文件名
  直接放 `x-filename` 会报错；服务端小函数自己解 `%XX`（不为这一处引
  `percent-encoding`）。

上传是 `POST /api/attachment`，body 就是文件原始字节（不是 multipart）。
服务端**按魔数**认图片 / PDF，不信 `content-type`；图片走 `read` 读图同一套
缩放流水线，PDF 原样存（限 32MB）。返回的 `id` 在发送时随 `/api/chat` 的
`attachments` 一起交出去，服务端把它拼进**那一条** user 消息的内容块
（`image_url` / `file`）。

已上传未发送的附件在输入框上方显示成胶囊：**上传中给转圈，失败给红条 +
下方一整行原因，成功才把缩略图/文件名填进去**。没这层反馈的话，大图上传
那几秒界面上什么都没发生，用户根本不知道选中的文件到底进没进来。发送后清空。

> 附件进历史用的是单独的 `ChatMessage::UserFiles`，**不是**把 `User(String)`
> 改成结构体。老会话里存的是 `{"User":"…"}`，改了就读不出来了；而且
> 正文和附件必须在**同一条**消息里，才不会被增量同步的切点切开。

### 模型药丸 = 选择模型 + 思考强度

药丸上写的是「**模型名 · 当前思考强度**」（强度 muted，`lib/effort.ts` 的
`effortLabel`）—— 一眼能看出现在用的是什么、要等多久。点它开的不是直接选模型，
而是**选择模型**面板：

```
        选择模型
   模型提供商   OpenCode Go ›   ← 切到第二页：只列配好了 Key 的几家，选一家看它的模型
┌───────────────────────┐
│ DeepSeek V4 Flash     │  ← 这一家 /models 拉回来的清单（筛掉 embedding/语音/画图）
│ DeepSeek V4.1 Flash ✓ │     当前那个打勾，清单内部自己滚
│ …                     │     点了模型才真的切过去（Key 在设置页里各存一份）
└───────────────────────┘
   思考强度          中等 ›   ← 切到第二页
```

两个子页（模型提供商 / 思考强度）共用轨道上的第二个位置，不排成三页 —— 从第一页
滑到第三页会把中间那页也扫一遍。「模型提供商」页最下面一行「管理模型提供商」
打开设置页（添加 / 删除 Key）。

### 上下文圆环 = 用量一眼可见

药丸右边一个环（`ContextMeter.svelte`），环里的数是**当前上下文占模型窗口的
百分比**，点一下弹面板看明细。

- **环本身就画满 36**（和「+」那个圆钮、发送键一样大），**不套一层底色圆** —— 它
  是读数，不是按钮底色；点它的热区也是这 36。面板里那个是同一段 snippet 放大到 56。
- **不着色**：弧线和数字用 `muted`/`fg`，轨道 `muted/30` —— 这一屏不需要再多
  一套语义色（ok/warn/bad 已经在工具结果、diff 那些地方用了），用了多少看百分比
  和弧长就够了。
- 明明有量却不到 0.5%（1M 窗口的头几轮就是这样，实测第一句 prompt 才 1468）时
  环里写 **`<1`** 而不是 `0` —— 写 0 看着像坏了；面板和 tooltip 那边给一位小数
  （`0.1%`）。

- **分子** = 最近一次请求的 `prompt_tokens`。它同时就是「现在这段上下文有多大」
  （整段历史 + 系统提示词 + 工具定义），比累计值更能说明还剩多少余量。
- **分母** = 模型窗口，来自 models.dev（`/api/models` 里那个 `context_window`，
  `lib/models.svelte.ts` 的 `contextWindow()`）。**没收录的模型不编假上限**：
  环只剩一条轨道、panel 里写「不知道这个模型的上限」——宁可空着也不骗人。
- 面板里四行：上下文（用/上限）、最近一次调用（输入/输出，思考单列一行）、
  缓存命中（命中 token / 输入 = 命中率）、本会话累计（输入/输出、调用次数、
  总命中率）。文案里写清楚每个数的口径，不让人猜。
- 数据两个来源：流里的 `data-usage`（每步结束一条 → 环实时跟着涨）和
  `/api/session` 的 `usage`（刷新 / 切会话回来时的基线）。累计值以**服务端**
  为准 —— 流里那些增量只是两次拉取之间的临时账。
- 服务端那份是 `AppState.usage`（会话 id → 用量），**只在内存里**：它是「现在
  这个上下文用了多少」的仪表盘，重启后从下一次调用重新数就行，不值得为它去动
  会话的存储格式。删会话 / 清空历史时跟着清掉。
  `GET /api/session` 的 `usage` 字段就是它。
- 一次 LLM 调用都没跑过时**不占位**（那一行本来就窄，空放一个灰圈只是噪声）。

### 设置页

抽屉左下角的齿轮、或者模型面板「模型提供商」页的「管理模型提供商」进来（`Settings.svelte`，全屏页面
`Page.svelte`：从右滑入，返回键 / 跟手返回 / 往右拖都能关，叠着开时先关最上面那页）。

「模型提供商」一栏是固定几家（`core/src/providers.rs`）：OpenAI、DeepSeek、OpenCode Go、
OpenCode Zen，外加「其他（OpenAI 兼容）」。内置的只填 API Key —— Base URL、协议、
首选模型都写死在 `PRESETS` 里；「其他」要自己填 Base URL（Ollama、中转站）。

- 保存时**先验证**：用这个 Key 拉一次 `/models`，401/403 就不存（`models::verify`，
  不走 models.dev 兜底，否则错 Key 也会「验证通过」）。
- 第一次配、或者改的是当前这家：顺手切过去（首选模型按 `preferred` 挑），
  填完 Key 就能聊。
- 删掉当前这家：切到另一家配好了的；一家都不剩就没有当前模型。
- 接口：`GET /api/providers`（只回 Key 的最后 4 位）、`POST|DELETE /api/providers/{id}`、
  `GET /api/models`（`groups` 按家分组，各家并行拉、后端缓存 10 分钟 —— 实测命中 15ms，
  强制直连上游 1.7–4s）、
  `POST /api/model {model, provider}`（`provider` 给了别家就切过去）。

- **不写模型描述**。Claude 每行下面有一句「适用于复杂工作与日常任务」，那是
  给它几个自家模型手写的；我们这里是 `/models` 拉回来的任意清单
  （OpenCode Go 有 38 个），没有描述可写，也不该编。
- **清单在前端也缓存一层**（`web/src/lib/models.svelte.ts`，TTL 10 分钟和后端对齐）。
  面板是 `{#if sheet}` 挂出来的，**每开一次都是一个新组件**；清单存在组件里的话，
  打开时第一帧只有「一行：载入中…」，十几毫秒后 38 行到了面板再长高 —— 那就是
  用户看到的**布局跳动**。后端缓存解决不了这个（它省掉的是「打扰上游」，实测
  命中缓存 15ms 就返回了），要消灭跳动得让**第一帧就有数据**，缓存必须比组件
  活得久。开机还会预拉一次（`App.svelte`），所以第一次打开也是瞬间的。
  过期不是不能用：先拿旧的渲染、背后悄悄重拉，界面不闪。设置页关一次会加一个
  `rev`，和缓存上记的对不上就强制重拉（Key 可能改了）。
- **模型清单单独滚**（`max-h-[42dvh]`）：38 行会把「思考强度」推到屏幕外，
  得先划过 38 行才点得到。给清单一个高度上限，下面两块就永远在视野里。
- **思考强度是同一个面板的第二页**，不是就地展开、也不是再叠一层：
  档位（默认 / 极低 / 低 / 中等 / 高）映射到 `reasoning_effort`
  （Chat 顶层字符串）/ `reasoning.effort`（Responses 嵌套对象）。**默认档 =
  一个字段都不发** —— 严格网关见到不认识的参数会直接 400。
- **翻页动效是原生 CSS**：两页并排放在一条 `w-[200%]` 的轨道上，
  `transform: translateX(0 | -50%)` + `transition` 就是那个平移；面板高度也跟着
  当前页走（同样是 CSS 过渡，所以切页时面板一起长高/变矮）。JS 只干两件事：
  记「现在哪一页」、量一下两页的自然高度（`height: auto → auto` 没法过渡）。
- **第二页不画返回箭头**：安卓本来就有返回键/返回手势。返回键在 `Sheet` 的
  `goBack` 里被接管 —— 第二页按返回是退回第一页，第一页才关面板。
  > 坑：跟手返回（预测性返回）commit 的那一下走的是 `peek.onEnd(true)`，
  > 早先这里直接调了 `close()`，于是「在第二页手势返回」把整个面板关了。
  > 现在 `drag.onEnd` 和 `onBack` 都走同一个 `goBack()`。
- **第二页的跟手返回是横移，不是下滑**：`Sheet` 收一个 `peek`，有 `onback` 时
  预测性返回的进度喂给它 —— 第一页从左边跟着手指滑回来（高度按进度插值），
  面板本身不动。手势开始时定下用哪套，整段不换。
- **清单内部滚动不关面板**：`canStart` 从手指落点往上找到面板，任何一层
  `scrollTop > 0` 都不接管 —— 只看正文的话，在已经滚下去的模型清单里往下划，
  正文 scrollTop 是 0，整个面板就被拉走了。
- 换页时长 `PAGE_MS = 450`（轨道平移、高度、标题飞入共用）；300 太急。

### 长对话：只挂一窗 + 增量同步

两条都是为了长任务 / 长会话：

- **窗口化**：DOM 里只保留最后 40 条消息，往上翻到顶再补一窗（补完把
  `scrollTop` 加上新增高度，视口里那条不动）。这才是真把节点数和内存封顶的
  那个。这里的「条」是**消息**（用户/助手），不是工具调用 —— 一个回合的思考、
  工具、正文都是同一条助手消息里的 parts，所以 40 条 ≈ 20 个回合。
  另外工具输出内联只渲染一行摘要按钮，真正的 50KB 输出只在点开面板时才渲染。
- **不再用 `content-visibility: auto`**：本来给「已经说完的」消息加它，省离屏
  消息的布局/绘制。实测**每次回复结束都会跳回这条消息的开头**：加类那一帧
  先按 `contain-intrinsic-size`（6rem）量了一遍，长回复被判定「对用户不重要」
  而整条跳过（12956px → 1838px），`scrollTop` 被夹到新上限（12371 → 1238），
  下一帧高度恢复但夹掉的 `scrollTop` 不恢复。而「说完话」正好是 `msg.done`
  翻 true、这条拿到类的那一刻。详见 `MessageList.svelte` 里的注释。
- **增量同步**：轮询 `/api/session` 时服务端只重发「当前回合」那一段
  （`append: true` + `replaceFrom`），前面的历史不再每步重传。会话是
  只追加的，所以这么切是安全的；切点取「上一条是 User」，保证开头那个
  assistant 和完整视图的合并规则一致（有测试盯着）。

客户端合并时也**不整段 `JSON.stringify`**：只按 id 复用旧对象，且不复用
「上一轮的最后一条」（那个回合可能还在长）。

### 多会话

「最近对话」要有内容就得支持多会话，所以后端从单个 `ChatSession` 改成
`SessionStore { sessions, active }`：

```
GET  /api/sessions           列出（按 updatedAt 倒序）
POST /api/sessions           新建并切换（CLI/调试用）
POST /api/sessions/activate  切换
POST /api/sessions/delete    删除
GET  /api/session            当前会话的消息（前端 Message[] 形状）+ `usage`（token 用量）
GET  /api/search?q=…         跨会话搜消息正文（侧边栏搜索框）
POST /api/chat  {session}     发到指定会话（不给 = 活动会话；{fresh:true} 留给老客户端）
POST /api/stop  {session}     只停这个会话的回合
```

**标题取第一条用户输入的前 28 字** —— 和 Claude 一样，不用单独起名。

### 几个会话同时跑

「进行中」和「停止」都按会话记（`AppState::turns`）：可以在 A 里让它跑着，切到 B
再开一个。同一个会话同时只能有一个回合（`/api/chat` 回 409）。

- 前端本地只连**当前看着的**那个会话的流。切走时 `detach()` 只断开本地的流，
  **不**调 `/api/stop` —— 服务端那个回合照跑（它本来就不看 SSE 有没有人听）。
- 切回一个还在跑的会话：`/api/session` 的 `busy` 为真 → 输入卡片显示停止按钮、
  每 1.5 秒轮询。轮询的粒度是「一步」（assistant 消息一步结束才进历史），
  看不到逐字流出来。
- 抽屉里正在跑的会话有个闪烁的点（`/api/sessions` 的 `busy`）。

### 排队：agent 说话时也能发下一条

模型一边说话，用户一边还能打字 —— 这时按发送**不丢**：进队列，等这个回合收尾
再依次发出去。队列里那条**就画在正文末尾**，和已发送的用户消息**同一个气泡**
（`MessageList` 里同一个 snippet：同一套圆角/内边距/字号/最大宽度），只多一圈
**虚线**和左边一个 **×**（去掉它）。

- **虚线气泡 ≠ 落进历史**：它只在 `queue` 里，不在 `messages` 里。落进 `messages`
  就成了本地历史的一部分，而服务端此刻还没有它 —— 回合收尾那次同步会按服务端
  重写历史（id 全新、DOM 重建），气泡会被冲掉。发出去的那一刻才真的落成消息
  （`done: false` → `true`），样子几乎不变：看上去就是「虚线变实」。
- **× 挂在气泡左边、不挤进去**：那个位置本来就是空的（用户消息贴右）。挂出去
  气泡的宽度才和已发送的一模一样（挤进去就窄一圈）。
- **队列在前端**（`App.svelte` 的 `queue`），服务端一行没改。理由：一个回合的
  输出是**这条 SSE 流**在收（`applyChunk` 往本地消息里写），而服务端那条
  「一个会话同时只跑一个回合」（409）的约束不该为了排队破掉。排队本质上就是
  「等一会儿再发同一个请求」。
- **每条记着 `sid`**：回合在后台跑着时用户可能已经切走了。`flushQueue` 只发
  属于**当前**会话的那些，其他的在内存里排着，切回去才轮到。
- **什么时候发**：本地这条流结束（`run` 的 finally）、服务端从「在跑」变成
  「没跑」（轮询）、切回某条会话 —— 三条路都收敛到 `flushQueue`；它先看一次
  `/api/sessions` 里那个 `busy` 标记再发（本地流断了 ≠ 服务端收尾了，按停止时
  尤其是这样：abort 要传过去、服务端还得补上「已停止」的工具结果）。只看
  `busy`、**不拉历史**：没必要因此把本地消息换成服务端 id。
- **附件跟着排队**：`Upload` 早就上传过了（在服务端 `pending_attachments` 里），
  排队期间原样留着，发出去时再带上 id。
- **「新对话」要把 `serverBusy` 清掉**：新会话在服务端还不存在，一定没在跑；
  不清的话会留着上一条会话的状态，输入框要等一个轮询周期才解冻（而且队列会
  以为自己该排队）。
- 输入卡片右边：还在跑时是停止键；有字时**同时**给一个发送键（title 写明
  「排队发送」）—— 停止和排队是两个动作，不共用一个位置。空闲时发送键照旧
  一直在（暗着）。
- **按停止只停正在跑的那个回合**，队列照旧发（它们是两件事：停止是「别说了」，
  排队是「说完这条接着说」）。
- 删会话时属于它的队列一起清掉。

### 空会话不记录

「新对话」连点几次就会攒出一堆没说过话的空会话，重启后还在抽屉里占位。
所以**新建会话拖到第一句话才发生**：

- 前端点「新对话」**不请求服务端**，只清空本地视图（外加一个 `fresh` 标志）；
  第一句发出去之前才 `POST /api/sessions` 建会话，拿到 id 再发（`ensureSession`）
- 点了不发 → 什么都不发生（切到别的会话、刷新页面都会丢掉这个意图，
  因为服务端从头到尾不知道）
- 服务端还有三层兜底（`ChatSession::has_content()`，即“有没有消息”）：
  `list()` 不列空会话、`db::sync()` 不落盘（顺手把旧行删掉）、
  `db::load()` 不恢复 —— 调试端/CLI 直接 `POST /api/sessions` 建的、
  `/api/reset` 清空后的会话都不会在抽屉里占位；
  老版本攼下的空会话也会在下次 sync 时清掉
- 所以「新对话」点了几次、抽屉里就只有几条**真的说过话**的会话

我第一版给每行加了个常驻的 `×`。**那是错的** —— Claude 列表里干干净净，

长按实现：`pointerdown` 起 420ms 定时器，触发后置 `longPressed` 标志，

### 一个坑

打开抽屉刷新列表**不能只靠 `$effect(() => { if (drawer) ... })`**：
抽屉一直开着的时候 `drawer` 状态没变化，effect 不会重跑 ——
在别处新建了会话，抽屉里还是「还没有对话」。改成打开时显式调用。

## 5. 顺手修的一个真问题

**消息只活在 WebView 的 JS 内存里。** Activity 重建 / 页面刷新 / 从后台
回来就空了 —— 实测切出去再回来对话没了。

而服务端的 `ChatSession` 一直留着完整历史。所以加了：

```
GET /api/session   →  转成前端 Message[] 的形状
```

前端 mount 时拉一次。`session_view()` 会把 assistant 的 `tool_calls` 和
后续的 `Tool` 结果配起来，还原成带 `tool` part 的消息。

## 6. 覆盖层与返回手势

抽屉、查看器、思考/工具面板都是**页内覆盖层**（不是 Android 的 Activity/Fragment），
所以返回键得自己接（`web/src/lib/overlay.ts`）：

- 打开时 `history.pushState` 一条，返回触发 `popstate` → 关掉**最上面**那一层
- 任何别的方式关掉（点遮罩、拖走、代码里卸载）→ 卸载时把那条 history 退回去，
  并跳过随之而来的那次 `popstate`（不跳的话会误关下一层）

### 预测性返回（跟手）

Android 13+ 的系统返回手势会把**进度**交给 App（壳注册 `OnBackInvokedCallback`，
见 docs/04 §5）。覆盖层只要把自己的「拖拽三件套」登记进来：

```ts
$effect(() => onBack(closeViewer, drag));   // drag = { onStart, onMove, onEnd }
```

进度就是位移：`onMove(0.35)` → 这一层挪出去 35%（拖右/拖下都是它）。松手完成走
`onEnd(true)`（从当前位置接着收尾），撤回走 `onEnd(false)`（弹回原位）。手势把
覆盖层划到哪、松手怎么收尾，跟手指拖拽本来就是同一套位移，所以不重复写。

桌面浏览器没有这个钩子，手动模拟即可：

```js
window.__predictiveBack('start')
window.__predictiveBack('progress', 0.35)   // 查看器 x = 0.35 × 屏宽
window.__predictiveBack('cancel')           // 回 0
window.__predictiveBack('commit')           // 关掉，history 也退回一条
```

真机验证（Pixel 10 / Android 17）：返回手势划到哪覆盖层就挪到哪，中途截图能看到
查看器被推出 45% 露出后面的对话；划出去再退回原处会 `cancel` 并弹回；
没有覆盖层时按返回是系统自己处理（回桌面）。细节见 docs/04 §5。
