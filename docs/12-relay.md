# 12 · 换机器：一条路（局域网 / 中继）

这里说的「机器」是**跑着核心的那台机器**：手机、电脑，都一样。换机器**只有一条路**：
本机核心里的隧道。页面（手机 App 的 WebView、电脑上的浏览器都是它）加载
`http://localhost:<端口>/?k=…`，隧道按请求挑上游：

```text
页面 ──http──▶ 本机核心的隧道 ─┬─ `/api/machines*` ──────── 本机核心（明文 loopback）
                               └─ 其余 ─┬─ 局域网直连 ────┬─ TLS（只认那张证书）─▶ 那台电脑的核心
                                        └─ 经中继（只搬字节）┘
```

所以**一个宿主一套逻辑**：手机上的壳和电脑上的浏览器跑的是同一份代码，平台只差两件薄的
（发现和「谁来导航」，见 docs/11）。谁都能连谁 —— 手机连电脑、电脑连电脑、电脑连手机
（只要那台的核心在广播自己）。壳里没有「局域网还是中继」的分叉。

为什么要分成两个上游：那些 `GET/POST /api/machines*`（「我能连哪些电脑」「连上这台」
「忘掉那台」）问的是**你自己这台机器**的记账，答案在本机的库里。全转给那台电脑的话，
连着 A 的时候面板会在 B 的库里查，永远是空的。**一份实现**：隧道只是把这几条转发回本机，
页面直接开本机地址时和经隧道时走的是同一个 handler（`http.rs` 的 `machines_*`）。

出了门局域网就断了：手机找不到电脑，电脑在家里的 NAT 后面也连不进去。中继补上这一段 ——
一台有公网 IP 的服务器（**不需要域名**），两头都主动连它，它把两边接起来：

```text
家里电脑的核心 ──HOST（主动连出去，一直挂着）──▶ 中继 ◀──DIAL── 外面的手机
               ◀──CONNECT <票>────────────────
               ──ACCEPT <票>（为这次新开一条）─▶  两条接上，之后只搬字节
```

## 页面不拿凭据：隧道替它带上

页面手里只有一把**隧道钥匙**：`connect` 给它的地址是 `http://localhost:<端口>/?k=<钥匙>`，
第一次请求（那一下 `?k=`）隧道换成一个 HttpOnly cookie（`agent_tunnel`），钥匙就不再露面。
每台电脑的 token 由隧道在转发时注入 `x-agent-token` —— 页面里的 JS 看着自己的 `location`、
翻自己的 history，都拿不到「那台电脑的 shell」。壳（WebView）那边要订阅那台电脑的回合状态
（通知栏，见 docs/06），核心另外给它一份带 `t=` 的地址（`machines::Conn::shell_url`），
那是壳自己的 HTTP 客户端，不经过页面。

反过来，**隧道这边也要凭据**：手机上有网络权限的任何 App 都能连 `127.0.0.1`，扫一遍端口
就能找到隧道 —— 不设防的话它连上就等于拿到那台电脑的 shell。`/api/*` 只认那把隧道钥匙
（或者那台电脑自己的 token —— 壳的回合状态订阅、核心里「出门在外怎么连」那次对账都走
后者）。页面、js/css、沙箱文件不设防：那本来就是公开的代码，沙箱文件另有一把路径上的钥匙。

## 连接复用

隧道是个按**请求**选路的 HTTP/1 代理（hyper）：页面那头 keep-alive，每个请求自己选上游
（`/api/machines*` 归本机，其余归那台电脑）；上游连接进池复用，同一条上游连接上来来去去的
只会是发往同一个上游的请求。

为什么要复用：经中继时一条新连接是「连中继 + CONNECT/ACCEPT + TLS 握手」好几个往返，而页面
每 1.5 秒轮询一次 `/api/session` —— 不复用的话每个请求都要付一遍。

池子里的连接可能已经死了却没人知道（手机换了网络，旧网络上的连接不会收到任何通知）。所以
池子的键里带着一个**路由代号**：网络一变（壳报 `network_changed`）、或者该换路了（发现服务
报了新地址、或者正走着中继时在局域网里又看到了那台电脑），代号加一，新请求不再用旧连接；
旧的空闲 30 秒后自己关掉。

长连接（SSE / WebSocket）照旧：SSE 就是一个流式的响应；WebSocket 两头各自升级，然后对搬字节。
切换机器时旧隧道收掉：不再接新连接，页面那头挂着的连接答完手上那个请求就断。

## 用起来是什么样

1. 服务器上装中继：`just relay-deploy`（不带参数 = 自己那台 `vihv@129.211.71.14`；
   换服务器：`AGENT_RELAY_HOST=user@ip just relay-deploy`。交叉编译 + scp + systemd，见下）。
   最后会打印两行 `AGENT_RELAY=…` / `AGENT_RELAY_KEY=…`。
2. **只在一台**电脑上配：把这两行写进仓库根目录的 `.env.local`，重启 `just dev-host`。
   终端里会说「出门在外：经中继 …」，日志里有「已连上中继」。
3. 任何一台机器**在家里的 Wi-Fi 里**连一次这台电脑（配对过的点一下就行）—— 它记下这台
   电脑的证书指纹和中继。
4. **其余的电脑什么都不用配**：在家连上它们时，发现它们还没有中继，就把自己知道的那个
   交过去（`POST /api/remote/relay`）。那台电脑立刻挂上、记在库里（`relay` 表），
   下次启动照样挂；日志里说一句「已把中继交给…」。
5. 出门以后，「选择机器」面板里那台电脑变成「经服务器连」，点一下就连上。
   界面、命令、文件和在家一模一样。它没连上中继（关机了、断网了）的话，那一行灰着、写
   「离线」，点不了 —— 面板开着时本机核心去问中继「这几台谁在线」（`ONLINE`，要密钥，
   结果缓存 10 秒）。中继是老版本、或者问不到时就是「不知道」，照常让人点。

中继配置的来源按顺序：环境变量（设了就以它为准，界面改不了）→ 别人交过来、记在
库里 `relay` 表的那份。能调 `/api/remote/relay` 的本来就拿着这台电脑的凭据（= 能在
上面跑命令），没有多给出什么。

面板里同一台电脑**只出现一次**：局域网里找得到就只显示直连那条；找不到（出门了）才显示
经服务器那条。连着的局域网直连断了（拿着手机出了门），隧道会**自动**改走中继，不用回到面板
（选路每条连接各选各的：先试局域网 ≤0.5 秒，不通就 30 秒内直接走中继，跑着的那条断了则
下一条连接自然重选 —— 见 `Routes`）。
回到家，面板里直连那条又出现了，点一下就换回直连。

## 安全

配对得到的 token 等于家里这台电脑的 shell，**绝不能明文过公网**。所以：

- **端到端 TLS，中继看不到内容。** 家里的核心第一次用时生成一张自签证书（存在
  `~/.local/share/android-agent/remote/`，之后一直是这一张）。手机配对时记下它的
  SHA-256 指纹；经中继连过来时**只认这一张**（`tunnel.rs` 的 `Pinned`：比指纹，
  签名照常验 —— 证书是公开的，验签保证对面真有那把私钥）。中继、或者路上的任何人
  都冒充不了这台电脑。服务器被人拿下也拿不到会话内容和凭据。
- **中继自己的门：共享密钥 + 挑战-应答。** 中继第一次启动时生成一把 32 字节的密钥。
  握手时中继先给一个随机数，对面回 `HMAC-SHA256(密钥, 角色|id|随机数)`：密钥不过网，
  抓到的握手重放不了。没密钥的人既不能冒充家里那台占位，也不能拿服务器当免费中转。
  密钥在配对时（和 `/api/remote`）交给手机 —— 手机本来就拿着 shell 的 token，
  再多一把中继的钥匙不改变什么。
- **局域网也是 TLS。** 电脑在**同一个端口**上同时认明文和 TLS（看第一个字节是不是 TLS
  握手，`http::accept_conn`）：电脑上自己开浏览器还是 `http://127.0.0.1:8787`，手机 App
  一律走 TLS —— token 不再在 Wi-Fi 上明文传。
- **配对也走 TLS。** 第一次配对时还不知道指纹：先收下对面的证书，再核对配对结果里它自己报的
  指纹和握手时看到的是同一张（`machines::Machines::pair`）。「人在电脑前、输对了码」就是
  信任的起点；之后只认这一张。
- **经中继来的请求一律按外人对待。** 家里的核心把它们的对端地址记成 `0.0.0.0:0`
  （`remote::RELAY_PEER`），所以「电脑自己来的不要凭据」（`trust_loopback`）对它们
  永远不成立 —— 哪怕中继就跑在这台电脑上。`/api/pair` 也不接（403，见 `http::Via`）：
  配对码只该在局域网里输，不然公网上有中继密钥的人能来猜（猜错五次还会把配对整个停掉）。
- **家里不开端口。** 电脑主动连出去；中继只听一个端口。

## 形状

| 部分 | 在哪 | 做什么 |
|---|---|---|
| 中继服务器 | `relay/`（独立小 crate，二进制 `agent-relay`） | 接线 + 搬字节；状态只有「谁在线」「哪些拨号在等」 |
| 握手协议 | `relay/src/lib.rs`（`connect` / `run_host`） | 两头的核心共用这一份 |
| 一条连接怎么服务 | `core/src/http.rs`（`serve_conn` / `accept_conn`） | 明文、局域网 TLS、中继**三种连接走同一个函数**、同一份路由；区别只在挂上的对端地址和 `Via` |
| 被连的那头 | `core/src/remote.rs` | 证书（局域网 TLS 和中继共用）、挂在中继上、运行时换中继（别人交来的） |
| 机器管理 | `core/src/machines.rs` | 配对过哪些电脑（库里的 `machines` 表）+ 局域网里看到的、配对（TLS）、连接、把中继交给还没配的电脑、页面上那份列表（`panel`） |
| 隧道 | `core/src/tunnel.rs` | 本机代理：按请求挑上游、注入凭据、每条连接**选路**（先局域网 0.5 秒，不通走中继，冷却 30 秒）+ TLS（只认那个指纹） |
| 界面（面板） | `web/src/components/MachineSheet.svelte` + `lib/machines.svelte.ts` | 问核心要那份列表（`GET /api/machines`）、配对、切换 —— 手机和电脑共用这一份 |
| 发现 | `CoreDiscovery.kt`（手机）/ `desktop::browse`（电脑） | mDNS 浏览，报给核心（`lanFound` / `lanLost`） |
| 壳 | `Remote.kt`（~110 行） | 只记「现在连的是哪台」；认不认页面给的那个地址（换页面时） |

几个选择：

- **一条用户连接对应一对 TCP**（本机那条 + 那台电脑为它新开的那条），不在一条连接上做多路复用。
  中继因此没有自己的帧格式，代码很小；代价是每条新连接多一次往返（隧道复用上游连接，摊薄了它，
  见上面「连接复用」）。
- **本机这头是代理，不是让页面直连。** 浏览器/WebView 不认「只信这一张证书」；而且页面来自
  `localhost`，算安全上下文（局域网直连 `192.168.x.x` 不算）。
- **用 `localhost` 而不是 `127.0.0.1`**：本机核心的页面在 `127.0.0.1` 上（cookie 按主机名分），
  隧道那条在自己的 `localhost:<端口>` 上 —— 两边的 cookie 不会互相覆盖，本机那份 `agent_token`
  也不会被带到那台电脑那边去。
- **选路在核心、每条连接各选各的。** 局域网地址来自 mDNS（见 docs/11）和上次记下的那个；
  先试它最多 0.5 秒，不通（出门了、换了 IP、那个 IP 上已经是别的设备 —— 证书对不上也算）就走
  中继，接下来 30 秒直接走中继。网络一变就重新先试局域网。两条都不通：隧道回一页 502 写明原因，
  App 那边看到 502 就回本机、弹一句为什么。
- **连上之后在后台对一遍**（`GET /api/remote`，经同一条隧道）：中继是配对之后才配的、
  或者换了服务器，都不用重新配对；它还没有中继就把手机知道的交过去。
- **中继只用纯 Rust 依赖**（tokio + hmac + sha2，没有 ring / C 代码），所以在 macOS 上用
  `rust-lld` 就能直接交叉编译出 Linux x86_64 的静态二进制（~0.7MB），服务器上什么都不用装。
- **连不上时说人话。** 拨号失败 / 指纹不对，隧道回一页 502 写明原因（先把请求读掉再回 ——
  带着没读的数据关连接，系统会发 RST，浏览器只看到「连接被重置」）。

## 部署

```sh
just relay-build            # → relay/target/x86_64-unknown-linux-musl/release/agent-relay
just relay-deploy           # 默认 vihv@129.211.71.14（ssh 用 vihv 登，sudo 免密）
AGENT_RELAY_HOST=user@1.2.3.4 just relay-deploy   # 换一台服务器
RELAY_PORT=9000 just relay-deploy                 # 换端口
```

服务器只认公钥（root 不能直登），所以 ssh 用 `vihv@` + 本机那把 `~/.ssh/id_ed25519`。
验证装上去的是不是刚编的那份：md5 对一下 ——
`sudo md5sum /usr/local/bin/agent-relay` 应该等于本机那个二进制的 md5。

`deploy-relay.sh` 把二进制装到 `/usr/local/bin/agent-relay`，写一个 systemd 服务
（`DynamicUser`，不用 root 跑；密钥在 `StateDirectory` 里，`/var/lib/agent-relay/key`），
开启并启动，装了 ufw 就顺手放行端口，最后打印家里要设的两行。再跑一次就是升级（密钥不变）。
中继升级不影响老的客户端（握手里多认一句 `ONLINE`，别的不变）；新客户端碰上老中继，
「谁在线」问不到，面板退回「不知道」。
**云服务器的安全组**得自己去控制台放行 TCP 8790。

不用 systemd 的话，直接跑也行：

```sh
AGENT_RELAY_LISTEN=0.0.0.0:8790 AGENT_RELAY_KEY_FILE=/var/lib/agent-relay/key ./agent-relay
```

## 验证（2026-10-14，本机）

自动测试：`relay` 5 条（拨号接通双向搬字节、对方不在线、密钥不对被拒、mac 绑定随机数和角色、
参数校验）；`core` 的 `remote::tests::a_phone_reaches_the_home_core_through_the_relay` 在一个
进程里跑真中继 + 家里那头（真路由）+ 手机那头的隧道：带凭据 200、不带 401（中继也在本机，
照样要凭据）、`/api/pair` 403、`/api/remote` 带指纹、指纹不对 502、对方不在线 502。

手动（真二进制：本机中继 + 一个独立数据目录的临时核心 + `cargo run --example tunnel`
扮演手机）：首页 200、`/api/health` 不带凭据 401、`/auth` 种 cookie 后 200、经中继配对 403、
`/api/ws` 升级 101、`/api/turns/stream` 首帧正常；把中继杀掉再起，家里那头 2 秒内自己接回来，
中间那段隧道回的是说明页。

```sh
# 扮演出门在外的手机（参数从家里那台的 /api/remote 拿：电脑上 curl 127.0.0.1:8787/api/remote）
cargo run --manifest-path core/Cargo.toml --example tunnel -- <实例id> <指纹> <那台电脑的 token> \
  [--lan IP:端口] [--relay IP:端口 密钥] [--local 127.0.0.1:8787]
```

### 换机器（2026-10-14，本机）

`remote::tests::a_computer_switching_to_another_one_keeps_the_panel_on_itself`：两个核心
（A 是「我在这台电脑」，B 是「另一台」）真的在本机跑起来，走完整的局域网 TLS + 配对 +
隧道：经隧道 `/api/health` 是 **B** 的、`/api/machines` 是 **A** 的（列表里能看到 B、
`current` 是它）、没带钥匙的请求 401、`/?k=` 换成 HttpOnly cookie（钥匙不对 403）、
`disconnect` 之后那个端口没人听了。`tunnel::tests` 另外盯住逐请求那一层：凭据只认钥匙或
那台机器的 token、转发时换成上游那一把、升级请求（WebSocket）不动 `connection`。
`machines::tests` 盯面板那份列表（看到的在前、只能经中继的在后、看不到又没中继的不列）。

手动（真浏览器，A=8791 / B=8790 两个核心 + 两台都在广播 `_agent-core._tcp`）：
`avahi-browse` 报进来的列表里正确剔掉了自己、剔掉了 docker0/utun 的假地址（这台开发机上
同时有 172.17.0.1 和 198.18.0.1）；页面上点 B → 输配对码 → 页面自己导航到
`http://localhost:<端口>/` 并渲染出 B 的界面；在那个页面上再开「选择机器」，列表仍然是
**A 的**（连着的那台带勾）、点「这台电脑」回到 `127.0.0.1:8791`；`/api/ws` 经隧道升级 101、
首页和 163 KB 的 js 都拉得下来。
